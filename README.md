# Обработчик файлов _p и _t (ExcelProcessor)

**Простая инструкция для пользователей.**  
Эта программа автоматически обрабатывает пары Excel-файлов с измерениями (давление и термопары) и собирает из них **одну итоговую таблицу**.

**Статус проекта:** публичный релиз `0.1.0`, готовый для аккуратного использования и проверки на реальных наборах данных. Ядро обработки покрыто автоматическими тестами; графический интерфейс проверяется вручную.

## Инженерная позиция

Проект следует принципам Chroma Engineering: корректность, безопасность данных и предсказуемость важнее скорости выпуска.

- Программа не изменяет исходные Excel-файлы.
- Существующие результаты не перезаписываются: для повторного запуска добавляется числовой суффикс.
- Алгоритм сопоставления явно разделён на чтение Excel, поиск строки критерия, синхронизацию по времени и экспорт.
- Ограничения и предположения описаны в README, чтобы пользователь видел, где заканчиваются гарантии инструмента.

## 1. Что делает программа

Представьте, что у вас в папке лежат файлы измерений:

- `26_06_2026_100000_p.xlsx` — **давление** (файл с суффиксом `_p`)
- `26_06_2026_100000_t.xlsx` — **термопары** (файл с суффиксом `_t`)

Программа для **каждой пары** делает следующее:

1. Открывает файл `_p` и ищет строку, где значение давления **ближе всего** к тому числу, которое вы ввели (например, `4.47`).
2. Берёт время (`Time*`) из этой строки.
3. Находит такое же время в файле `_t`.
4. Копирует нужные столбцы (термопары + давления) в **одну строку** итоговой таблицы.
5. После обработки всех пар сохраняет **один файл** с результатом в ту же папку.

**Вам не нужно вручную открывать Excel и искать строки — программа делает это сама.**

## 3. Первый запуск

При первом запуске программа сама создаст локальное окружение `.venv` и установит зависимости.

### macOS (MacBook и т.д.)

1. Откройте **Терминал** (Программы → Утилиты → Терминал, или через Spotlight: напишите «Терминал»).
2. Перейдите в папку с программой:

```bash
cd /путь/к/Analyzer
```

> Замените путь, если папка лежит в другом месте. Проще: перетащите папку `Analyzer` в окно Терминала — путь подставится сам.

3. Запустите программу:

```bash
python3 start.py
```

При первом запуске это может занять немного времени: Python создаст `.venv` и скачает зависимости.

4. Если появилась ошибка про `tkinter`:

```bash
brew install python-tk@3.14
```

5. Готово. Установка больше не понадобится.

### Windows

1. Откройте **cmd** или **PowerShell**.
2. Перейдите в папку с программой:

```bat
cd C:\путь\к\Analyzer
```

3. Запустите программу одним из способов:

```bat
run.bat
```

или:

```bat
py start.py
```

> `py` — это Windows Python Launcher. На macOS такой команды обычно нет, там используйте `python3`.

## 5. Пошаговая инструкция

**Для тех, кто пользуется впервые — делайте строго по шагам:**

### Шаг 1. Запустите программу

См. [раздел 4](#4-как-запустить-программу).

### Шаг 2. Выберите папку

1. На вкладке **«Обработка»** нажмите **«Обзор»**.
2. Укажите папку, где лежат ваши файлы `_p` и `_t`.
3. Нажмите **«Сканировать»** — программа посмотрит структуру файлов и подготовит списки листов и столбцов.

> Если написано «Пары _p/_t не найдены» — проверьте [имена файлов](#6-как-должны-называться-файлы).

### Шаг 3. Настройте профиль (один раз или при смене оборудования)

1. Перейдите на вкладку **«Настройки»**.
2. Проверьте **листы** (`_p` и `_t`) — обычно данные на втором листе.
3. Проверьте **столбцы** — критерий, Time*, префиксы.
4. Нажмите **«Сохранить профиль»**.

> Если не уверены — оставьте профиль **«Базовый профиль»**, он подходит для типовых файлов с измерениями.

### Шаг 4. Введите целевое давление

На вкладке **«Обработка»** в поле «Целевое значение критерия» введите число, например:

```
4.47
```

Можно с запятой: `4,47` — программа поймёт.

### Шаг 5. Проверьте (необязательно, но полезно)

Нажмите **«Проверить»**. Внизу в логе появится:

- сколько пар найдено;
- есть ли ошибки (нет нужных столбцов и т.д.);
- предупреждения (файлы без пары).

### Шаг 6. Запустите обработку

Нажмите **«ЗАПУСТИТЬ»**. Следите за прогресс-баром и текстом внизу.

### Шаг 7. Найдите результат

Итоговый файл появится **в той же папке**, откуда брались исходники:

- `26_06_2026.xlsx` — имя строится по **самой ранней дате** среди обработанных пар.

Если файл с таким именем уже есть, программа не перезапишет его: новый результат будет сохранён как `26_06_2026_1.xlsx`, затем `26_06_2026_2.xlsx` и так далее.

## 6. Как должны называться файлы

### Стандартный формат (по умолчанию)

| Тип | Суффикс | Пример |
|-----|---------|--------|
| Давление | `_p` | `26_06_2026_100000_p.xlsx` |
| Термопары | `_t` | `26_06_2026_100000_t.xlsx` |

**Базовое имя** (без суффикса) должно совпадать: `26_06_2026_100000`.

### Формат даты в имени

Рекомендуемый вид: `ДД_ММ_ГГГГ_ЧЧММСС`

Пример: `26_06_2026_153045_p.xlsx` — 26 июня 2026, 15:30:45.

### Поддерживаемые расширения

- `.xlsx` — основной формат
- `.xls` — старый Excel
- `.xlsb` — бинарный Excel

### Что будет, если пара неполная

| Ситуация | Что делает программа |
|----------|----------------------|
| Есть `_p`, нет `_t` | Файл `_p` пропускается, в логе предупреждение |
| Есть `_t`, нет `_p` | Файл `_t` пропускается |
| Оба есть | Обрабатывается |

| **Сканировать** | Читает первую пару файлов, показывает доступные листы и столбцы |
| **Целевое значение** | Число, по которому ищется строка в файле `_p` (обычно давление) |
| **Активный (профиль)** | Выбор сохранённого набора настроек |
| **Новый** | Создать пустой профиль настроек |

| **Импорт** | Загрузить профиль из файла `.json` |

| **Ход выполнения** | Текстовый лог — читайте при ошибках |

## 8. Вкладка «Настройки» — все поля

### Общие

| Поле | Описание | Значение по умолчанию |
|------|----------|----------------------|
| **Имя профиля** | Название набора настроек | Базовый профиль |
| **Суффикс _p** | Окончание имени файла давления | `_p` |
| **Суффикс _t** | Окончание имени файла термопар | `_t` |
| **Режим критерия** | Как искать строку в `_p` | см. таблицу ниже |
| **Допуск Time*** | Насколько точно должно совпасть время между `_p` и `_t` | `0.000001` |
| **Потоков** | Сколько пар обрабатывать одновременно (ускорение) | `4` |
| **Писать JSON-отчёт в dry-run** | Сохранять подробный отчёт при тестовом запуске | включено |

#### Режимы критерия

| Режим | Значение | Когда использовать |
|-------|----------|-------------------|
| `closest` | Ближайшее значение к введённому числу | **Обычно этот** |
| `above` | Ближайшее значение **не меньше** заданного | Нужен момент «достигли или превысили» |
| `below` | Ближайшее значение **не больше** заданного | Нужен момент «ещё не превысили» |

### Листы

| Поле | Описание |
|------|----------|
| **Лист _p** | Какой лист читать в файле давления (часто второй — `Data` или индекс `1`) |
| **Лист _t** | Какой лист читать в файле термопар |

> После **«Сканировать»** можно выбрать лист из выпадающего списка.

### Колонки (столбцы)

| Поле | Описание |
|------|----------|
| **Критерий (_p)** | Столбец, по которому ищется строка (обычно `pressure_ai0`) |
| **Time* (_p / _t)** | Столбец времени для синхронизации двух файлов |
| **Префикс _p / _t** | Если справа списки пустые — берутся все столбцы с этим началом имени |
| **Данные _p** | Какие столбцы давления попадут в результат (пусто = по префиксу) |
| **Данные _t** | Какие столбцы термопар попадут в результат (пусто = по префиксу) |

#### Как выбрать столбцы вручную

1. Слева — доступные столбцы, справа — выбранные.
2. Выделите столбец слева → нажмите **→** (добавить).
3. Чтобы убрать — выделите справа → **←**.
4. **«По префиксу»** — добавить все столбцы, имя которых начинается с префикса (например, `pressure_ai`).

### Кнопки внизу

| Кнопка | Действие |
|--------|----------|
| **Сохранить профиль** | Запомнить все настройки |
| **Сбросить к умолчанию** | Вернуть стандартные значения базового профиля |

## 9. Профили — что это и зачем

**Профиль** — это сохранённый «рецепт» обработки:

- какие листы читать;
- какие столбцы брать;
- как искать критерий;
- в каком формате сохранять.

### Зачем несколько профилей

| Пример | Профиль |
|--------|---------|
| Стандартные файлы | Базовый профиль |
| Другой стенд, другие имена столбцов | Новый профиль «Стенд 2» |
| Только 3 термопары, не все | Профиль с ручным выбором столбцов |

### Как передать настройки коллеге

1. Настройте профиль.
2. **Экспорт** → сохраните `.json`.
3. Коллега нажимает **Импорт** и выбирает этот файл.

## 10. Форматы результата

| Формат | Файл | Когда выбирать |
|--------|------|----------------|
| `xlsx` | `26_06_2026.xlsx` | Обычная работа в Excel |
| `csv` | `26_06_2026.csv` | Для других программ, 1С, MATLAB |
| `both` | Оба файла сразу | Нужны и Excel, и CSV |

### Что внутри итогового файла

- Столбец времени (`Time*`) — реальное значение из файла `_p`.
- Столбцы термопар (`thermo_ai0`, `ai1`, …) — из `_t`.
- Столбцы давления (`pressure_ai0`, `ai1`, …) — из `_p`.
- Столбец **«Время»** — время из **имени файла** (для удобства чтения человеком).

Строки отсортированы **по дате** (от ранней к поздней).

## 11. Режим проверки без сохранения (dry-run)

Для опытных пользователей или для проверки перед реальной обработкой.

Запуск из Терминала:

```bash
python3 start.py --dry-run
```

На Windows: `run.bat --dry-run` или `py start.py --dry-run`.

Что произойдёт:

- файлы **не** будут созданы;
- в логе будет написано, **какие** файлы были бы созданы;
- появится JSON-отчёт `{дата}_dry_run_report.json` в папке с данными (если включено в настройках).

Полезно, чтобы убедиться, что всё настроено правильно, **не трогая** исходники.

## 12. Архитектура проекта

Проект разделён на небольшие модули, чтобы пользовательский интерфейс не смешивался с логикой обработки данных.

| Модуль | Ответственность |
|--------|-----------------|
| `start.py` | Подготовка локального `.venv`, установка runtime-зависимостей и запуск приложения |
| `main.py` | Точка входа GUI-приложения |
| `gui.py` | Окно, вкладки, ввод настроек, прогресс и сообщения пользователю |
| `config.py` | Профили обработки, пути настроек, режимы `--debug` и `--dry-run` |
| `excel_io.py` | Выбор движка Excel, чтение листов и колонок |
| `matching.py` | Числовой разбор данных, поиск строки по критерию и сопоставление по времени |
| `processing.py` | Оркестрация обработки пар, прогресс, отмена, dry-run |
| `export_results.py` | Формирование имён и сохранение `.xlsx`, `.csv`, JSON-отчётов |
| `tests/` | Автоматические проверки ядра обработки и конфигурации |

Ключевой поток данных:

1. Поиск полных пар `_p`/`_t` в выбранной папке.
2. Чтение только нужных колонок из Excel.
3. Поиск строки в `_p` по целевому значению критерия.
4. Поиск строки в `_t` по найденному `Time*`.
5. Сбор одной строки результата и экспорт итоговой таблицы.

## 13. Область релиза и ограничения

### Scope версии `0.1.0`

- GUI-обработка пар Excel-файлов `_p` и `_t`.
- Поддержка `.xlsx`, `.xls`, `.xlsb` через `pandas` и соответствующие движки.
- Режимы выбора критерия: ближайшее значение, не меньше цели, не больше цели.
- Настраиваемые профили листов, колонок, префиксов, формата результата и допуска `Time*`.
- Экспорт в `.xlsx`, `.csv` или оба формата сразу.
- Dry-run с JSON-отчётом.
- Автоматические тесты ядра обработки.

### Известные ограничения

- GUI пока проверяется вручную; автоматические тесты покрывают ядро без запуска окна.
- Производительность больших файлов зависит от `pandas`, формата Excel и выбранных колонок.
- Сопоставление `_p` и `_t` предполагает числовой `Time*`; при шуме во времени нужно настроить допуск.
- Программа не поставляется как `.exe` или `.app`; для публичной версии нужен установленный Python 3.10+.
- Доменные предположения о физических измерениях задаются пользователем через профиль и не заменяют проверку методики эксперимента.

### Проверка качества

## 14. Частые проблемы и решения

### «ModuleNotFoundError: No module named ...»

**Причина:** зависимости не установлены.

**Решение:**

```bash
cd /путь/к/Analyzer
python3 start.py
```

Если автоматическая установка не сработала:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
python3 start.py
```

---

### Окно не открывается (macOS)

**Причина:** нет поддержки графического интерфейса.

**Решение:**

```bash
brew install python-tk@3.14
```

---

### «Пары _p/_t не найдены»

**Проверьте:**

1. Файлы в **одной папке**.
2. Имена заканчиваются на `_p` и `_t` (или те суффиксы, что указаны в настройках).
3. Базовое имя совпадает: `XXX_p.xlsx` и `XXX_t.xlsx`.

---

### «В файле ... время ... не найдено»

**Причина:** в `_t` нет строки с таким же `Time*`, как в `_p`.

**Что попробовать:**

1. Увеличить **Допуск Time*** в настройках (например, `0.0001`).
2. Убедиться, что выбран **правильный лист** в обоих файлах.
3. Проверить, что столбец времени называется одинаково (или правильно указаны оба).

---

### «Нет колонки критерия ...»

**Решение:**

1. Нажмите **Сканировать**.
2. На вкладке **Настройки** выберите правильный столбец в **Критерий (_p)**.
3. **Сохранить профиль**.

Скорее всего, обрабатывает большие файлы. Подождите или нажмите **ОТМЕНА**. Прогресс-бар покажет движение.

## 15. Где программа хранит настройки и логи

### macOS

| Что | Путь |
|-----|------|
| Настройки и профили | `~/.config/ExcelProcessor/settings.json` |
| Лог работы | `~/.local/share/ExcelProcessor/Logs/processor.log` |

### Windows

| Что | Путь |
|-----|------|
| Настройки и профили | `%APPDATA%\ExcelProcessor\settings.json` |
| Лог работы | `%LOCALAPPDATA%\ExcelProcessor\Logs\processor.log` |

> `~` — это домашняя папка текущего пользователя.
